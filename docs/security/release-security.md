# Security release controls

CI blocks high and critical dependency reports across the complete server, website and mobile graphs. Audit fetch/parse failures also fail the job. There is no `continue-on-error`. Moderate findings remain visible and need continuing remediation; a green policy gate does not mean there are no advisories. Exact build-only exceptions are recorded in `dependency-exceptions.json` with scope, owner role, rationale and expiry. An exception cannot suppress a critical or unrelated new advisory. Assign a named reviewer before a production security sign-off and review these exceptions before they expire.

The website now uses patched Next 15 and a static-asset-only service worker. Financial pages, APIs, uploads, authenticated requests and private/no-store responses are excluded. Legacy page caches are removed on activation. Production CSP no longer permits eval. Mobile uses the patched image-size parser; `scripts/patch-metro-image-size.cjs` adapts Metro's legacy synchronous filename input to bytes and fails if Metro changes the expected source. Reassess/remove that adapter when upgrading Expo/Metro.

The credential scan includes committed examples and documentation and reports only location/category. It checks high-confidence provider/private keys, SMTP passwords and database credentials. It is not a complete entropy/history scanner or a substitute for repository-provider secret scanning. Example mail credentials found during this work were removed; revoke/rotate any previously committed mail credential and review provider usage and Git history. Removal does not revoke a credential or erase prior copies. Never add a new credential to Git.

Production new money activity requires private review evidence bound to the deployed SHA; shared coordination and integrity failures block movement. API request ids are server generated, sensitive log fields and HTTP error configs are redacted, and protected metrics use a separate bearer secret. Existing legacy log call sites still require periodic data-leak review; no redaction pattern proves all sensitive prose is safe.

Before launch, complete an independent web/API ASVS and mobile MASVS review, penetration test, separate custody-compromise drill and credential/role review. Test access-control boundaries with real provider identities, callbacks and physical devices. All outside attestations remain pending until actual evidence is reviewed. Set required CI contexts on the default branch; do not rely solely on a green historical build or permit force-pushing around review.
